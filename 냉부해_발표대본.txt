냉부해 발표 대본
================================

1페이지 (표지): 안녕하세요. 저희 팀 프로젝트 '냉부해'를 발표하겠습니다. '냉부해'는 '냉장고를 부탁해'의 줄임말로, AI가 식재료를 사진 한 장으로 인식하고 보유한 재료에 맞는 레시피까지 추천해 주는 스마트 식재료 관리 서비스입니다. 오늘은 이 서비스를 왜 만들게 되었는지, 어떤 기능이 있는지, 그리고 기술적으로 어떤 점에 신경 썼는지 순서대로 말씀드리겠습니다.

2페이지 (목차): 발표는 크게 네 부분으로 진행됩니다. 먼저 이 서비스가 왜 필요한지 개발 배경을 말씀드리고, 두 번째로 자동 인식·맞춤 추천·사용자 편의로 이어지는 핵심 기능 세 가지를 소개하겠습니다. 세 번째로는 시스템 아키텍처와 기술적 차별점을, 마지막으로 이 프로젝트의 기대 효과를 정리하겠습니다.

3페이지 (개발 배경): 저희가 주목한 문제는 크게 두 가지입니다. 첫째, 1인 가구와 맞벌이 가정이 늘면서 유통기한이 지난 식재료가 그대로 버려지고, 이게 매년 심각해지는 음식물 쓰레기 문제로 이어지고 있습니다. 둘째, '오늘 뭐 먹지?'라는 고민이 매일 반복되면서 배달 음식에 의존하게 되고 영양 불균형이 생깁니다. 기존 앱들은 유통기한이나 영양 정보를 일일이 손으로 입력해야 해서 번거롭다는 한계가 있었습니다. 저희는 바로 이 두 문제를 동시에 해결하고자 했습니다.

4페이지 (솔루션 한눈에): '냉부해'의 해결 방식을 한 문장으로 정리하면 '사진 한 장으로 끝내는 식재료 관리'입니다. 크게 세 가지 기능으로 구성됩니다. 첫째, 사진을 찍으면 AI가 식재료를 자동으로 분류해 입력해 주는 '자동 인식', 둘째, 보유한 재료와 취향을 분석해 레시피를 제안하는 '맞춤 추천', 셋째, 유통기한 알림으로 낭비를 막는 '수명 연장'입니다. 지금부터 이 세 가지를 하나씩 자세히 보여드리겠습니다.

5페이지 (핵심 기능 1 · 자동 인식): 첫 번째 핵심 기능은 'AI 식재료 자동 인식'입니다. 사용자가 식재료를 촬영하면 Vision AI가 사진에서 이름과 카테고리를 즉시 추출합니다. 여기서 중요한 점은, AI 예측에만 의존하지 않고 그 결과를 식약처 공공데이터 API와 크로스체크한다는 것입니다. 또 자체 구현한 유사도 기반 매칭 알고리즘으로 100그램당 영양 성분까지 신뢰성 있게 가져옵니다. 결과적으로 수동 입력을 사실상 없애서, 사용자가 앱을 계속 쓰게 만드는 재방문율을 높이는 핵심 기반 기술입니다.

6페이지 (핵심 기능 2 · 맞춤 추천): 두 번째 기능은 'LangChain 기반 맞춤형 추천'으로, 세 단계로 동작합니다. 1단계, 현재 냉장고에 있는 식재료의 종류와 잔여량, 유통기한 데이터를 수집합니다. 2단계, LangChain을 활용해 AI에게 '영양 전문 푸드 컨설턴트'라는 페르소나를 부여하고 이 데이터를 프롬프팅합니다. 3단계, 사용자의 취향, 즉 한식·중식·일식과 영양 밸런스를 고려한 세 가지 맞춤 요리와 조리 팁을 돌려줍니다. 단순 검색이 아니라 내 냉장고에 맞춘 추천이라는 점이 차별점입니다.

7페이지 (핵심 기능 3 · 사용자 편의): 세 번째는 사용자 편의성을 높이는 기능들입니다. 먼저 카카오·구글·네이버를 통한 소셜 로그인을 지원해서 진입 장벽을 낮췄습니다. 두 번째로 FCM 푸시 알림을 활용해, 유통기한이 임박한 식재료는 오전 9시에, 레시피 추천은 식사 시간 직전에 알려서 앱을 능동적으로 쓰도록 유도합니다. 마지막으로 냉장고 공유 기능을 통해 가족이나 룸메이트를 초대해 재고를 함께 투명하게 관리할 수 있습니다.

8페이지 (시스템 아키텍처): 시스템은 역할에 따라 세 계층으로 분리한 마이크로서비스 지향 구조입니다. 첫째, 프론트엔드는 Flutter 기반 크로스 플랫폼으로 iOS와 안드로이드를 한 번에 대응하고, 카메라 접근과 부드러운 UI/UX를 담당합니다. 둘째, 백엔드 서버는 Java Spring Boot로 비즈니스 로직과 보안을 맡아 JWT 인증, Supabase PostgreSQL 통신, FCM 알림 발송을 처리합니다. 셋째, AI·데이터 서버는 Python FastAPI로 고성능 비동기 처리를 하며 Gemini API 호출과 LangChain 파이프라인, 공공데이터 연계를 담당합니다. 이렇게 계층을 분리해 유지보수성과 확장성을 확보했습니다.

9페이지 (기술적 차별점): 기술적으로 강조하고 싶은 차별점은 두 가지입니다. 첫째, 데이터 자가 보정 파이프라인입니다. 공공데이터 API 결과가 모호하거나 누락돼도 단순 에러로 처리하지 않고, LLM이 스스로 검토·보정해서 프론트엔드가 요구하는 정확한 JSON 형태로 반환합니다. 둘째, 보안과 성능입니다. JWT Refresh Token Rotation으로 토큰 탈취와 재사용을 차단하고, 업로드 용량을 제한해 서버 메모리 부족, 즉 OOM 현상을 방어했습니다.

10페이지 (기대 효과): '냉부해'가 만드는 변화는 세 가지 측면으로 정리할 수 있습니다. 환경 측면에서는 유통기한 관리로 버려지는 식재료를 줄여 음식물 쓰레기와 탄소 배출 저감에 기여합니다. 건강·경제 측면에서는 정확한 영양 분석 기반 레시피로 식습관을 개선하고, 가진 재료를 100퍼센트 활용해 불필요한 중복 구매를 막습니다. 기술 측면에서는 단순한 CRUD 앱을 넘어, 프롬프트 엔지니어링과 LLM 에이전트 기반의 상용화 수준 아키텍처를 실제로 구현했다는 의미가 있습니다.

11페이지 (감사합니다): 이상으로 '냉부해' 발표를 마치겠습니다. 사진 한 장으로 식재료를 관리하고, 버려지는 음식을 줄이면서, 매일의 식사 고민까지 덜어주는 서비스입니다. 끝까지 들어주셔서 감사합니다. 질문 있으시면 편하게 말씀해 주세요.
